# SciReader EN–RU — проект формата данных

Дата: 2026-11-05. Статус: предложение для эксперимента, не утверждённая JSON Schema. Принято только использование единого структурированного формата. Точные поля, система координат и упаковка уточняются после прототипа и вопросов Q-02/Q-07/Q-08 из [журнала](decisions.md).

## 1. Принципы

- Разделять оригинальный PDF, нормализованный английский текст, перевод, математическую запись и визуальные привязки.
- Постоянные ID не зависят от порядкового номера в массиве или имени файла.
- Хранить версию схемы и версию распознанного текста. Исправление перевода не обязано менять версию английского текста.
- Один фрагмент может содержать несколько областей PDF и несколько русских предложений.
- Перевод принадлежит статье, а отрывки ссылаются на её фрагменты. Не создавать независимые копии перевода для пересекающихся отрывков: исправление общее. Последняя позиция чтения хранится отдельно от начала отрывка и пользовательских контрольных точек.
- Явно различать ручную правку и автоматический результат. Сохранение не означает проверку качества.
- Не доверять входному файлу: проверять формат, ссылки, размеры и принадлежность статье до применения.

## 2. Предлагаемые сущности

| Сущность | Основные поля | Назначение |
| --- | --- | --- |
| Document | schemaVersion, articleId, sourceHash, sourceFile, metadata, textRevision | Идентичность статьи и неизменяемого PDF; одинаковое имя не означает одинаковый источник |
| Block | id, kind, order, segmentIds | Заголовок, abstract, абзац, подпись и другие категории, влияющие на включение в подсчёт |
| Segment | id, blockId, sourceParts, sourceRanges, reviewStatus | Предложение или отдельная структурная единица; заголовок не нужно искусственно считать предложением |
| TextPart | kind=text, text, sourceMapping | Нормализованный английский текст и соответствие исходным диапазонам |
| FormulaPart | kind=formula, formulaId | Явная математическая часть, целиком исключённая из счётчика |
| Formula | id, latex, spokenEn, sourceRegions, reviewStatus, revision | LaTeX, английское чтение и области на исходной странице |
| Translation | segmentId, parts, revision, editedByUser, reviewStatus | Русский текст с отдельными ссылками на формулы |
| Excerpt | id, articleId, textRevision, start, end, targetCount, actualCount, countPolicyVersion | Сохранённый отрывок с воспроизводимой политикой подсчёта |
| Checkpoint | id, articleId, textRevision, position, quoteContext | Позиция и контекст для проверки после исправлений |
| TranslationRequest | requestId, articleId, sourceHash, textRevision, segmentIds, sourceDigest | Связь результата внешнего ИИ с конкретным запросом |

Это логическая модель, не требование использовать отдельный файл или таблицу для каждой сущности. Не хранить PDF как строку base64 внутри каждого отрывка.

## 3. Текст и координаты

Предлагаемое логическое положение: `segmentId + partId + offset`. Единицу offset (Unicode-кодовые точки или графемы) необходимо согласовать с политикой подсчёта, затем использовать одинаково во всех компонентах. JavaScript UTF-16 length не считать автоматически окончательной спецификацией.

Исходная привязка хранит страницу и диапазон текстовых элементов. Для отображения используется набор прямоугольников или четырёхугольников. Выбор и единицы координат подтвердить экспериментом; соглашение о нумерации страниц и повороте обязательно записать до реализации импорта.

Одна логическая позиция после удаления типографского переноса может соответствовать нескольким частям источника. Нельзя восстанавливать координаты только по поиску строки: одинаковая фраза может встречаться несколько раз.

Ручные области формулы отделены от автоматических диапазонов. При обновлении извлечения существующая ручная привязка не заменяется без сравнения.

## 4. Пример частей фрагмента

Иллюстрация формы, не валидируемый полный документ:

```json
{
  "id": "segment-example",
  "sourceParts": [
    { "kind": "text", "text": "The value " },
    { "kind": "formula", "formulaId": "formula-example" },
    { "kind": "text", "text": " is updated." }
  ],
  "translation": {
    "parts": [
      { "kind": "text", "text": "Значение " },
      { "kind": "formula", "formulaId": "formula-example" },
      { "kind": "text", "text": " обновляется." }
    ],
    "editedByUser": false,
    "reviewStatus": "unreviewed"
  }
}
```

В счётчик попадают только разрешённые текстовые части английского оригинала. Формула не исчезает из предложения и отображения из-за исключения из счётчика.

## 5. Обмен с внешним ИИ

Запрос должен содержать версию формата, идентификатор запроса, идентичность статьи/версии текста, список фрагментов и инструкцию. Полезный контекст передаётся отдельно от переводимого отрывка, чтобы модель не включала его в результат.

Ответ связывает переводы с выданными segmentId, а сведения о формулах — с formulaId. Координаты и исходные ID не изобретаются моделью. При необходимости первоначального распознавания формул их результат рассматривается как предложение для сверки, а не как подтверждённая геометрия.

Проверки перед применением:

1. Поддерживаемая версия и правильные типы полей.
2. Совпадение запроса, статьи и версии текста.
3. Отсутствие неизвестных и повторяющихся ID; явное сообщение о пропусках.
4. Сохранность оригинального английского текста, если он возвращён в ответе.
5. Корректность ссылок на формулы и допустимость их содержимого для рендерера.
6. Предпросмотр изменений относительно текущего перевода и ручных исправлений.

Частичный импорт, повторный импорт того же ответа и применение старого ответа после правки исходного текста должны иметь явно заданное поведение. По умолчанию предложение: блокировать неоднозначные изменения, не блокируя чтение уже сохранённого материала. Это ещё нужно закрепить в сценарии.

## 6. Перенос и миграции

Предложение: переносимый архив включает оригинальный PDF и один JSON документа с переводами, формулами и точками. Экспорт всей библиотеки обсуждается вместе с Q-02. До выбора упаковки не назначать расширение файла как окончательное.

При импорте проверять соответствие хеша PDF, все ссылки на сущности и версию схемы. Перед миграцией сохранять возможность восстановления; неизвестную более новую схему не перезаписывать старой. Точная политика копий — Q-09.

Изменение нормализованного текста создаёт новую textRevision. Отрывки и точки старой версии нуждаются в проверке соответствия; числовые смещения не переносятся молча.
