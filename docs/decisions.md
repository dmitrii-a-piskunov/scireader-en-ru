# SciReader EN–RU — решения проекта

Дата исходного согласования: 2026-11-05. Принято пользователем в диалоге и аннотациях; при противоречиях пользователь указал приоритет более поздней аннотации. Запись в этом файле не означает, что функция реализована.

## Принятые решения

| ID | Решение | Основание / следствие |
| --- | --- | --- |
| D-01 | Использовать [общие правила сотрудничества](ai-working-agreement.md) и проектный AGENTS.md | Учитывать цель, обсуждать существенные противоречия, сохранять существующие правки. |
| D-02 | Вести один `docs/decisions.md` | Поздняя аннотация допускает его вместо отдельных ADR. При росте проекта перенос в ADR обсуждается отдельно. |
| D-03 | Первая версия для компьютера, личное использование, без дополнительных расходов | Не требовать платный сервер, API или новую подписку. Перенос через облачную папку допустим. |
| D-04 | Слева оригинальный PDF, справа русский перевод | Заменяет прежнюю идею обязательно восстанавливать английскую HTML-вёрстку. Качество привязок проверяется экспериментом. |
| D-05 | Поддерживать PDF с текстовым слоем | Сканы и OCR за пределами первой версии. Наличие слоя не гарантирует безошибочное извлечение. |
| D-06 | Единый структурированный формат связанных фрагментов | Два независимых текста не обеспечивают устойчивую подсветку и импорт. Точная схема пока проектируется. |
| D-07 | React + TypeScript + Vite, PDF.js, MathJax, PWA, Playwright | Стек принят. Версии и дополнительные библиотеки ещё не выбирались. |
| D-08 | GitHub Pages | Статическое размещение. Подготовка каркаса не означает публикацию. |
| D-09 | Папка при поддержке браузером, IndexedDB как запасной режим; импорт/экспорт в обоих | Использовать подход hotkey-map. Полноценная автоматическая многопользовательская синхронизация не согласована. |
| D-10 | Внешний ИИ с ручной передачей подготовленных данных — обязательный путь v1 | Встроенный API возможен позднее как дополнение. Сохранённые материалы и исправления не зависят от одного сервиса. |
| D-11 | Кандидаты для проверки перевода: имеющийся ChatGPT Plus и бесплатный DeepSeek | Качество и соблюдение формата не проверены. Claude Pro не является обязательным инструментом. |
| D-12 | Старт от слова или контрольной точки, с обозначением неполного начального предложения | Пользователь управляет началом отрывка. |
| D-13 | После N непробельных символов закончить текущее предложение | Не обрывать на N; не принимать сокращения и десятичные точки за конец. |
| D-14 | Заголовки и abstract учитывать; формулы, таблицы, рисунки и их подписи исключать | Формулы исключаются целиком, а не только LaTeX-команды. Таблицы и рисунки остаются видимыми в PDF, ссылки на них сохраняются. |
| D-15 | Формулы: LaTeX, английское чтение, интерактивная подсказка и ручная правка | Редактируются LaTeX, чтение и область на PDF. Оригинальный PDF не меняется. |
| D-16 | Озвучка текста/слов и доступ к словарю | Конкретные голоса, словарь и возможность встраивания сайта ещё исследуются. |
| D-17 | home-reading не нужен как активный скилл | Извлечь требования, исключить глоссарий, DOCX, Obsidian и сдачу. Сохранить исходник как контекст. |
| D-18 | Сохранить примеры в `references/`, создать документационный каркас | Пользователь разрешил перенос; содержимое исходников сохранено. Код и зависимости на этом этапе не добавляются. |

Дополнение от 2026-11-05 по согласованию сценария:

| ID | Решение | Основание / следствие |
| --- | --- | --- |
| D-19 | Библиотека «статья → несколько отрывков» с общим переводом | PDF хранится один раз; исправление перевода отражается во всех пересекающихся отрывках. |
| D-20 | Независимая и связанная прокрутка переключаются кнопкой; между панелями визуальная фигура связывает соответствующие фрагменты | Уточнение пользователя по аналогии с diff-просмотром. Наведение подсвечивает без скачков; выбор показывает пару. Режим по умолчанию и детализация соединителей пока открыты. |
| D-21 | Предпросмотр границ до сохранения и подготовки перевода | Старт от слова, точки или фактического конца прошлого отрывка. Позиция чтения хранится отдельно. Готовый перевод переиспользуется, повторный перевод запускается явно. |
| D-22 | Установить общую инструкцию в глобальный AGENTS.md и дополнить её проектным | Выполнено по явному запросу; config.toml не менялся. Переносимая копия остаётся в проекте. |
| D-23 | Связанная прокрутка по умолчанию; соединитель выбранного или наведённого предложения | Принято пользователем после D-20. Связи всех видимых фрагментов одновременно не требуются. |
| D-24 | Название SciReader EN–RU, имя репозитория `scireader-en-ru` | Принято пользователем. Заменяет предварительное название; уникальность бренда не проверялась. Создание удалённого репозитория этим решением не выполняется. |
| D-25 | Сверять только выбранный отрывок, без обязательного подтверждения каждого предложения | Действие «Проверить текст» позволяет исправлять символы, переносы и границы предложений; непроверенный материал остаётся доступен без ложной отметки качества. |
| D-26 | Исправление привязки отдельным действием; перевод и формулы редактируются в карточке предложения | Пользователь заново указывает текст или область PDF. ИИ возвращает перевод, LaTeX и английское чтение; механику выделения и качество распознавания проверить прототипом. |
| D-27 | После коммита документации начать ограниченный PDF-прототип | Явный запрос пользователя. Реализованный срез и ограничения — в [отчёте](prototype.md); публикация не выполнялась. |
| D-28 | Каждое математическое вхождение открывает чтение прямо у формулы | Явное уточнение пользователя: формулы одного предложения доступны отдельно, как в PDF, так и в переводе. |
| D-29 | Связанная прокрутка выравнивает начало опорной пары по вертикали | Учитываются ограничения страниц и доступного диапазона; положение сохраняется при выборе и смене масштаба. |
| D-30 | Выбор и Esc не меняют геометрию текста и не оставляют рамку на предложении | Действия с привязкой вынесены в постоянную панель; Esc снимает также наведение и фокус предложения. |

## Открытые вопросы

Q-01 и Q-02 ниже закрыты в основном объёме; открытые детали вынесены отдельно.

Это вопросы, а не принятые требования. Рекомендации не считаются согласованными автоматически.

| ID | Вопрос | Предложение / когда решить |
| --- | --- | --- |
| Q-01 | Закрыт: переключение независимой/связанной прокрутки и визуальные соединители | D-20; детали в Q-12. |
| Q-02 | Закрыт: библиотека статей и отрывков, общий перевод, продолжение | D-19/D-21. Объём экспорта остаётся в Q-08, удаление/именование точек — детали будущего UI. |
| Q-03 | Закрыт в части сценария: сверка выбранного отрывка и отдельное исправление привязки | D-25/D-26. Конкретную механику выделения проверить прототипом. |
| Q-04 | Как обрабатывать внешнее изменение файлов и работу на нескольких устройствах? | Рекомендация: последовательная работа, обнаружение конфликтов перед записью, без автоматического слияния в v1. |
| Q-05 | Какой словарь, нужен ли встроенный просмотр, какие режимы озвучки? | Проверить выбранный сервис. Базовый переход надёжнее неподтверждённого iframe. |
| Q-06 | Точный список ОС/браузеров и минимальная ширина окна | Основные настольные браузеры остаются целью; определить матрицу, включая реальные проверки Safari. |
| Q-07 | Детали подсчёта: keywords, библиография, цитаты, примечания, Unicode и конец в заголовке | Зафиксировать до реализации счётчика. Не считать текущую схему окончательной. |
| Q-08 | Формат переносимого файла и включение PDF | Рекомендация: один архив статьи с PDF и JSON; подтвердить после модели библиотеки. |
| Q-09 | Резервные копии, срок хранения, история изменений и отмена | Не переносить число копий из hotkey-map автоматически. Согласовать достаточный объём защиты. |
| Q-10 | Способ выбран: внешний ИИ возвращает перевод, LaTeX и чтение; остаётся проверить качество и контракт | D-26. Эксперимент на статье; не обещать автоматическую точность любого сервиса. |
| Q-11 | Закрыт: SciReader EN–RU / `scireader-en-ru` | D-24. |
| Q-12 | Закрыт: связанная прокрутка по умолчанию; соединитель выбранного/наведённого предложения | D-23. Детали отображения пары за пределами экрана проверить на макете. |

## Правило обновления

Добавлять дату и основание нового решения. При замене сохранять прежнее решение со статусом «заменено» и ссылкой на новое. Не отмечать эксперимент завершённым до появления результатов. Существенные разногласия между реализацией и документами выяснять, а не молча выбирать удобный источник.
